## 一、技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 前端框架 | **Next.js 14** (App Router) | SSR 做 Landing SEO；CSR 做占卜交互；社区成熟 |
| 前端样式 | **Tailwind CSS** | 快速出视觉，仪式感配色通过 design tokens 统一 |
| 前端动画 | **Framer Motion** + CSS Animation | 六爻逐行动画；龟壳摇晃；金光特效 |
| 后端框架 | **Python FastAPI** | 异步支持好；LLM 调用友好；排盘算法用 Python 写自然 |
| 数据库 | **SQLite** (MVP) → PostgreSQL (扩展) | MVP 零部署依赖；SQLAlchemy ORM 保证切换无痛 |
| 认证 | **JWT** (python-jose + passlib) | 无状态；适合 API 前后端分离 |
| LLM 调用 | **httpx** 异步请求 | FastAPI 原生异步；不引入 LangChain 等重框架 |
| TTS | 预留接口，MVP 不做 | P1 再选型（Edge TTS / 豆包 TTS） |
| 部署 | 单服务器 Docker Compose | 前端静态导出 + 后端 uvicorn |

### 安全边界（关键）

```
前端                     后端                        外部
─────────────────────── ────────────────────────── ──────
                         prompts.py (隐藏)
提问问题 ──────────────→ 加载 prompt 模板
                        拼上用户问题
                                              ─────→ LLM API
                                              ←───── 判词
                        只返回判词文本
判词展示 ←────────────── (不含 prompt，不含 key)
```

- Prompt 模板和 API Key 不存在数据库里，不经过网络传输给前端
- Prompt 存代码文件（`backend/app/divination/prompts.py`），部署时只存在于服务器内存
- API Key 通过环境变量注入，`.env` 不入 git

## 三、模块设计

### 3.1 排盘引擎 `divination/engine.py`

纯函数模块，零外部依赖。输入：无（随机起卦）。输出结构化结果。

```
起卦流程：
1. 模拟三钱抛掷 6 次
2. 每次：3 枚铜钱 → 正(3)反(2) → 和 = 6/7/8/9
   - 6：老阴 ⚋ → 变爻 → 之卦为 ⚊
   - 7：少阳 ⚊ → 不变
   - 8：少阴 ⚋ → 不变
   - 9：老阳 ⚊ → 变爻 → 之卦为 ⚋
3. 初爻(最下) → 上爻(最上)，逐爻构建
4. 查表得本卦名、之卦名、互卦名

输出数据结构：
{
  "original": {
    "name": "风雷益",
    "trigram_upper": "巽",     # 上卦
    "trigram_lower": "震",     # 下卦
    "lines": [7, 8, 8, 9, 7, 7],  # 从初爻到上爻
    "binary": "100011"          # 阳=1 阴=0，初爻在右
  },
  "changing_lines": [3],        # 变爻位置（0-indexed 从初爻起）
  "transformed": {
    "name": "风火家人",
    "lines": [7, 8, 7, 9, 7, 7]
  },
  "mutual": {
    "name": "山地剥"
  },
  "rarity": "R"                 # N/R/SR/SSR，基于稀有度表
}
```

### 3.2 Prompt 模板 `divination/prompts.py`

**此模块不在前端暴露，不经过 API 返回给客户端。** 仅在服务端拼装 prompt 后直接发送给 LLM。

```python
# 示意结构（实际内容隐藏在 prompts.py 中，不入版本管理可见的明文）
SYSTEM_PROMPT = """你是一位精通周易六爻的占卜师..."""

JUDGMENT_TEMPLATE = """
用户问题：{question}
所得卦象：{hexagram_name}（上{trigram_upper}下{trigram_lower}）
变爻：第{changing_lines}爻
之卦：{transformed_name}

请生成判词...
"""
```

### 3.3 LLM 调用封装 `llm/client.py`

- 异步 httpx 客户端
- 支持多个 provider（DeepSeek 为主，可切换）
- 超时控制 + 重试
- 响应解析为纯文本

### 3.4 翻译模块 `translation/`

- 复用 LLM 接口
- 不同语言的翻译 prompt 模板
- 翻译结果缓存（同一卦象 + 语言组合不重复翻译）

### 3.5 认证模块 `auth/`

- 手机号 + 验证码（MVP 可先做邮箱密码，手机号 P1）
- 邮箱 + 密码
- JWT access token（短期）+ refresh token（长期）

## 四、数据模型

```sql
-- 用户
users (
    id          UUID PRIMARY KEY,
    email       VARCHAR UNIQUE,
    phone       VARCHAR UNIQUE,        -- P1
    password_hash VARCHAR NOT NULL,
    subscription VARCHAR DEFAULT 'free', -- free / monthly / yearly
    created_at  TIMESTAMP DEFAULT NOW()
)

-- 占卜记录
readings (
    id              UUID PRIMARY KEY,
    user_id         UUID REFERENCES users(id),
    question        TEXT NOT NULL,
    -- 卦象数据
    hexagram_orig_name  VARCHAR,       -- 本卦名
    hexagram_orig_lines VARCHAR(6),    -- "788977"
    changing_lines  JSON,              -- [2, 4] 变爻位置
    hexagram_trans_name VARCHAR,       -- 之卦名
    hexagram_mutual_name VARCHAR,      -- 互卦名
    rarity          VARCHAR DEFAULT 'R',
    -- 判词
    judgment_cn     TEXT,              -- 中文古诗判词
    judgment_raw    TEXT,              -- LLM 原始返回（调试用）
    -- 翻译（JSON，key=语言码）
    translations    JSON DEFAULT '{}', -- {"en":"...", "ja":"..."}
    -- 元数据
    created_at      TIMESTAMP DEFAULT NOW()
)

-- 卦象收集（P1）
collections (
    id          UUID PRIMARY KEY,
    user_id     UUID REFERENCES users(id),
    hexagram_name VARCHAR NOT NULL,      -- 卦名
    first_seen  TIMESTAMP DEFAULT NOW(),
    count       INTEGER DEFAULT 1,       -- 遇到次数
    UNIQUE(user_id, hexagram_name)
)

-- 每日配额
daily_quotas (
    id          UUID PRIMARY KEY,
    user_id     UUID REFERENCES users(id),
    date        DATE NOT NULL,
    count       INTEGER DEFAULT 0,
    UNIQUE(user_id, date)
)

-- 成就（P1）
achievements (
    id          UUID PRIMARY KEY,
    user_id     UUID REFERENCES users(id),
    achievement_key VARCHAR NOT NULL,
    unlocked_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(user_id, achievement_key)
)

-- 皮肤（P1）
skins (
    id          UUID PRIMARY KEY,
    user_id     UUID REFERENCES users(id),
    skin_type   VARCHAR,                -- 'turtle' / 'coin' / 'background'
    skin_id     VARCHAR,
    acquired_at TIMESTAMP DEFAULT NOW()
)
```

## 五、API 设计

### 认证

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/auth/register` | 注册 `{email, password}` |
| POST | `/api/auth/login` | 登录 `{email, password}` → `{access_token, refresh_token}` |
| POST | `/api/auth/refresh` | 刷新 token |

### 占卜

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/divination` | 起卦 `{question}` → `{reading_id, hexagram, judgment_cn}` |
| GET | `/api/divination/{id}` | 获取历史占卜详情 |
| GET | `/api/divination/{id}/translation?lang=en` | 获取翻译 |
| GET | `/api/divinations?page=1&limit=20` | 占卜历史列表 |

### 用户

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/user/profile` | 用户信息 + 今日剩余次数 |
| GET | `/api/user/collection` | 卦象收集进度（P1） |
| GET | `/api/user/achievements` | 成就列表（P1） |

### 健康检查

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/health` | 服务状态 |

## 八、天干地支扩展预留

当前 MVP 只做六爻核心（卦名 + 卦象 + 爻辞 + 变卦），暂不引入天干地支。但架构上预留扩展点：

- `divination/engine.py` 输出的数据结构中预留 `stem_branch: Optional[dict]` 字段
- `divination/data.py` 中预留 `纳甲表` 和 `六亲表`（数据已备但 MVP 不调用）
- 前端 `HexagramReveal` 组件预留干支显示区域（隐藏状态，P2 打开）
- 判词 prompt 中暂不提及干支，但模板结构上可以追加干支信息而不影响现有 prompt 逻辑

需要时只需：
1. 在 `engine.py` 中增加 `assign_ganzhi(hexagram, date)` 函数
2. 在前端打开对应显示区域
3. 更新 prompt 模板加入干支上下文
